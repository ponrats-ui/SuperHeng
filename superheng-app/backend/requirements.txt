# SuperHeng backend — Day 2 dependencies
#
# Install into the backend virtualenv:
#     cd backend
#     python -m venv .venv
#     .venv/Scripts/python -m pip install -r requirements.txt   # Windows
#     .venv/bin/python     -m pip install -r requirements.txt   # macOS / Linux
#
# Interpreter: Python 3.14.4 (verified on this machine). Every package below
# installs from a wheel with no build step — see "Verified stack" at the bottom.

# --- API service (main.py) -------------------------------------------------
fastapi>=0.143
# [standard] adds the watchfiles reloader (needed for --reload on Windows) plus
# httptools/websockets. Plain `uvicorn` has no reloader and silently ignores
# --reload, which is a confusing failure mode during development.
uvicorn[standard]>=0.54

# --- Database (Supabase / PostgreSQL) --------------------------------------
# Pulls postgrest-py, storage3, realtime and httpx.
supabase>=2.32
# Imported by name in auth.py, which reads `user_profiles` with a hand-written
# PostgREST request rather than through the supabase-py query builder.
#
# Why not the builder: `client.postgrest.auth(token)` sets the token on that
# client's *default headers*, and the client is a process-wide singleton shared by
# every concurrent request — so two interleaved entitlement checks would race and
# authenticate one caller's query with another's token. A per-request httpx call
# keeps the identity scoped to the call, and `httpx` is what that call is.
#
# `supabase` already installs it, but a module imported by name is declared by
# name: a transitive dependency that `supabase` is free to bump or drop must not
# be the only thing standing between a fresh clone and a working premium gate.
httpx>=0.28

# --- Payments (Stripe) -----------------------------------------------------
# Cards for international customers, PromptPay for Thai users. Used by exactly one
# module, `payments.py`, which owns the secret and the signature verification;
# `checkout.py` and `webhook.py` call through it rather than importing the SDK.
#
# The SDK version and the Stripe *API* version are different things. 16.0.0 speaks
# API version `2026-09-30.endive` by default, and `STRIPE_API_VERSION` pins the
# latter explicitly if you want that (see .env.example).
#
# One thing to know before a major upgrade: `SessionCreateParams` in this version
# has **no** `payment_method_types` key. It was replaced by
# `allowed_payment_method_types`, which filters Stripe's dynamically eligible
# methods rather than listing them statically — so PromptPay must also be enabled
# in the dashboard. A bump that renames a parameter again breaks checkout at
# *runtime*, not at install time, which is why `tests/test_payments.py` asserts
# that parameter by name.
stripe>=16

# --- Configuration ---------------------------------------------------------
python-dotenv>=1.2

# --- Ingestion (scraper.py / data_ingestion.py) ----------------------------
requests>=2.32
beautifulsoup4>=4.15      # HTML archive fallback parser
# Imported directly by data_ingestion.py (`from urllib3.util.retry import Retry`),
# which scraper.py imports in turn. `requests` already pulls urllib3 in, but a
# module imported by name should be declared by name: a transitive dependency
# that `requests` is free to bump or drop must not be the only thing standing
# between a fresh clone and a working ingestion run.
urllib3>=2.8
pandas>=3.0               # optional: CSV export in data_ingestion.py

# --- Advanced models (Day 5) -----------------------------------------------
# NOTE: statsmodels is imported lazily, inside /api/predict/advanced, not at
# module scope. `import statsmodels.tsa.arima.model` costs a measured 1738 ms on
# this machine, and a top-level import would add that to every uvicorn start,
# every --reload restart and every test run that merely imports main.
statsmodels>=0.15
# Declared as requested, and NOT yet imported by any backend module — there is no
# sklearn call in the Day 5 code. It is the baseline for the ML work the roadmap
# still has ahead: chronological train/validation splits and permutation
# importance for the LSTM tier (VISION §2.4), and rank aggregation for the
# scorecard. It pulls scipy, which statsmodels also needs, so the install cost is
# shared rather than additive. Stated plainly rather than given a token use to
# justify its presence.
scikit-learn>=1.9
# Imported directly by models/ensemble.py, models/montecarlo.py and
# models/timeseries.py (and by tests/test_models.py). pandas, statsmodels and
# scikit-learn all depend on numpy, so it arrives either way — but the API's own
# modules import it by name, so it is named here too, where it will be noticed
# if the dependency of those packages ever changes.
numpy>=2.5

# --- Development / tests (not needed to run the service) -------------------
# The Day 3 unit tests for the statistical models:
#     .venv/Scripts/python -m pytest -q
pytest>=9.1
